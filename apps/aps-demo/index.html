Agentic Process Safety: investigate AI agent workflow risk

The bearings are due Thursday.

A site needs 24 bearings for assembly. Planning sets the need date, a buyer checks stock and open orders, and sourcing confirms supplier terms. Finance authorizes a particular purchase. The release sends the order to the supplier. Receiving later records whether the bearings arrive.

What changes while the request waits?

A purchasing agent receives the earlier approval for 300 simulated spend units. It can still use the purchasing tool when that approval expires. Releasing the order could commit funds outside the authorization. Holding it leaves the next shift to find out whether the bearings are already on hand or on the way.

Before estimating savings, a site would count requests that waited beyond approval, measure handling time and match each need date to stock or receipts. The example gives no observed stockout or savings figure.

One second changes the order

A hazard and operability study (HAZOP) calls this deviation LATE. Two rules see the same request. At 59 seconds both release it. At 60 seconds the approval expires. A rule that checks permission and spend still releases the order, while a rule that also checks approval age holds it.

Who will cover Thursday’s run? A buyer checks incoming stock, confirms the quote and obtains current approval if the shortage persists.

What would you do?

Keep buyer-led purchasing, add the approval rule, or try a four-week shadow pilot with buyers retaining release authority. In the illustrative first-year investment case, three buyer minutes freed per request yield a $2,400 shortfall. At 4.5 minutes the proposal breaks even. Six minutes yield $2,400 of net capacity value. A site would have to verify the time freed and whether materials arrive on time.
